## The central architectural change

The client used to write money and scheduling documents directly. It no longer
does. Payments, customers, subscriptions, registrations, entitlements and the
counters are now written **only** by transactional Cloud Function callables, and
`firestore.rules` locks those collections to functions-only. This one shift is
what makes the money-integrity and tenancy fixes real rather than cosmetic.

New/rewritten functions (`functions/src/`): `lib.ts` (tz + money/VAT + idempotent
`applyPaidPayment` + invoice numbering + audit), `payments.ts`, `customers.ts`,
`booking.ts`, `subscriptions.ts`, `entitlements.ts`, `admin.ts`, `providers.ts`,
and `index.ts` (triggers + report). The old at-least-once `onPaymentWritten`
trigger is gone.

## Fixed — by finding ID

### Go-live blockers (P0)
- **P0-1 provisioning** — `provisionTenant` / `addOperator` / `removeOperator`
  callables guarded by a `vendorAdmin` claim; `scripts/grant-admin.mjs`
  bootstraps the first admin; `operators` subcollection; responses flag
  `refreshRequired` for the token-rotation delay.
- **P0-2 hosting** — `firebase.json` hosting block: `dist`, SPA rewrite, cache
  headers, `predeploy: npm run build`.
- **P0-3 icons** — real PNGs (192/512/maskable/apple-touch) generated by
  `scripts/gen-icons.py`; manifest fixed; a Vite build assertion fails on a
  missing icon.
- **P0-4 payment webhook** — `growWebhook` (signature verification stubbed for
  Q2) + a manual **"סמן כשולם"** action flip pending link/cash payments;
  nightly sweep expires stale pending payments.

### Money integrity (P1)
- **P1-1 idempotent stats** — stats move inside the single idempotent
  `applyPaidPayment` transaction, guarded by the `invoiceId` marker; a retry
  cannot double-count.
- **P1-2 transactional invoicing** — invoice number is allocated in the same
  transaction that stamps the payment marker and writes the invoice doc; the
  counter is **per-year** and the year comes from the studio-tz `createdAt`, not
  the server clock.
- **P1-3 server-side pricing** — `createPayment` prices every line from the
  product doc; the client's amount is never trusted.
- **P1-4 promo transactions** — the promo is re-validated and consumed
  (`usedCount++`) in the same transaction as the payment write — no oversell,
  no lost decrement.
- **P1-5 complete refunds** — `refundPayment` calls the provider, issues the
  credit invoice, reverses entitlement/subscription/stats/promo, supports
  **partial** amounts (`refundedAmount`), and the confirm dialog is disabled
  while pending.
- **P1-6 agorot** — money stored as integer agorot everywhere (`src/lib/money.ts`);
  one display boundary (`formatMoney`) and per-form entry conversion; seed +
  every price input migrated; unit-tested so net+VAT always sums to gross.
- **P1-7 VAT** — `tenant.vat` config; each sale snapshots a net/VAT/gross
  breakdown carried into the ledger and report; expenses post input-VAT lines;
  the report totals `vatCollected`.
- **P1-8 ledger period** — payments post to the period of their `createdAt`;
  refunds post to the current period and carry `originalPeriod`.
- **P1-9 immutable reports** — reports are versioned (`reports/{period}/versions/{n}`);
  `resendReport` re-sends the existing version, `regenerateReport` is an explicit
  new version.
- **P1-10 no delete of money docs** — rules deny delete on payments, expenses,
  invoices, ledger.

### Tenancy / security (P2)
- **P2-2 narrowed rules** — counters/ledger/invoices/reports/auditLog/operators
  are functions-only; payments/entitlements/subscriptions/registrations are
  client read-only; promoCodes allow create/update but freeze `usedCount`;
  expenses are create-only; tenant self-edit limited to
  name/logo/theme/classTypes/accountant/policy.
- **P2-3 entitlement consumption** — punches are consumed server-side at booking;
  rules lock entitlements to functions-only; an audited `adjustEntitlement`
  callable replaces free editing.
- **P2-5 storage limits** — receipts ≤10 MB images/PDF, logos ≤5 MB images,
  everything else denied.
- **P2-4 audit (partial)** — every callable writes an append-only `auditLog`
  entry. App Check and rate-limiting are **not** yet enabled (see below).

### Product surface (P3)
- **P3-1 subscription billing** — daily `chargeDueSubscriptions` bills via the
  mock provider (→ invoice+ledger), advances `nextChargeAt`, duns then cancels;
  pause records `pausedAt`, resume pushes the date, cancel stops at period end.
- **P3-2 booking** — `bookCustomer` / `cancelBooking` / `markAttendance`
  callables + a booking UI in `SessionSheet` (customer search, coverage choice,
  capacity guard, remove control); `registeredCount` is now maintained for real.
- **P3-3 settings** — a settings sheet (tap the header logo): name, brand
  colours, accountant, cancellation policy, class types, sign-out.
- **P3-4 product/instructor lifecycle** — product archive/restore; instructor
  deactivate/reactivate; template deletion wired with a referential guard.
- **P3-5 recurrence hygiene** — the recurrence toggle only appears in template
  *create* mode (no duplicate series); the materialiser warns on a dangling
  template instead of failing silently.
- **P3-6 entitlement expiry** — daily `expireEntitlements` flips lapsed punch
  cards to `expired`; products carry `validityDays`.

### Correctness (P4)
- **P4-1 missing index** — added the `registrations status+createdAt` index (and
  `attendedAt`, entitlement-expiry indexes).
- **P4-2 attended metric** — measures by `attendedAt`, not `createdAt`.
- **P4-3 recurrence form bug** — `AddSessionSheet` builds the series from the
  operator's edited form, not the stale template.
- **P4-9 date rollover** — `useToday` advances the header/home/week views across
  midnight and on tab refocus.

### UX / hygiene (P5, P7)
- **P5-1 error surface** — a module-level toast store lets the QueryClient's
  Mutation/Query caches funnel every failure into a Hebrew toast; an
  `ErrorBoundary` replaces the white-screen crash.
- **P5-2 confirm busy state** — `ConfirmDialog` disables while pending (kills the
  double-tap = double-action gap) on refund and subscription-cancel.
- **P7-1 tests** — Vitest suite (21): the `zonedTimeToUtc` +3h guard
  (winter/summer/round-trip), date-key arithmetic, agorot + VAT split,
  `validatePromo` (all branches), `sumLedger`.
- **P7-2 CI** — GitHub Actions runs typecheck, lint, tests, and both builds on
  every PR.
- **P7-3 hygiene** — `functions/lib/` removed from git and gitignored;
  `firebase-admin` aligned to v14 on both sides.

## Not done — deferred, with reasons

These are real remaining items from the review. None block the fixes above;
each is either large enough to deserve its own focused pass or lower priority.

**Security depth (P2-4).** App Check is not enabled and `resendReport` is not
rate-limited. App Check needs a reCAPTCHA key + enforcement config; the
`rateLimits` collection is reserved in the rules but no bucket check is wired.

**Booking depth (P3-2).** The booking UI resolves coverage server-side but does
not yet pre-show the customer's balance, and there is no waitlist. Late-cancel
policy fields exist (`tenant.policy`) but the cancel UI doesn't yet apply the
window automatically — it passes `lateCancel` only when set explicitly.

**Product editing (P3-4).** Products can be archived/restored but the price/name
edit form is create-only (archiving + re-creating is the current path). A full
edit form and a recurrence-management sheet (edit weekday/time/end a series)
remain.

**Dialog accessibility (P4-8).** `Sheet` still stacks its own Escape listeners
and lacks a focus trap; the recommended rebuild on native `<dialog>` +
`showModal()` is untouched.

**Midnight-crossing sessions (P4-4), conflict detection (P4-5), template→future
propagation (P4-6).** Not addressed.

**Scale (P6).** No pagination yet — lists still load whole collections;
`materialiseSessions` / `monthlyAccountantReport` still iterate tenants
sequentially; the bundle is still one chunk; Firestore offline persistence is
not enabled.

**Analytics redesign (P3-7)** and **customer deletion/export (P3-8)**: untouched.

**Money migration.** New data is agorot end-to-end and the seed is agorot. There
is **no migration script** for pre-existing production documents — there is no
production data yet, but if any exists it must be multiplied by 100 before this
deploys.

**Runtime verification.** Everything typechecks, lints, unit-tests and builds,
but the callables and rules were **not** exercised against the emulator in this
pass (the review environment didn't run it). Before deploy: run the emulator,
`npm run seed`, and walk the payment/refund/booking/subscription flows;
`@firebase/rules-unit-testing` coverage of the new rules is still to be written.
